# 테트리스 애플리케이션 개발 계획

## 1. 목표

FastAPI와 SQLite를 사용하는 백엔드와 프론트엔드를 연동해 다음 흐름을 제공한다.

1. 사용자가 이메일과 비밀번호로 회원가입한다.
2. 가입한 사용자만 로그인할 수 있다.
3. 로그인한 사용자가 테트리스를 플레이한다.
4. 게임이 종료될 때마다 점수와 게임 통계를 서버에 저장한다.
5. 모든 사용자의 기록 중 최고점수와 사용자 식별 정보를 화면에 표시한다.

## 2. 기술 기준

- 백엔드: Python 3.11 이상, FastAPI, Uvicorn
- 데이터베이스: SQLite
- ORM: SQLAlchemy 2.x 또는 SQLModel
- 스키마 검증: Pydantic v2, `EmailStr`
- 비밀번호 해시: Argon2 또는 bcrypt
- 인증: JWT 액세스 토큰
- 프론트엔드: 기존 구조 우선, 신규 구성이라면 React와 TypeScript 검토

## 3. 구현 단계

### 단계 1. 프로젝트 기반 구성

- 백엔드와 프론트엔드 디렉터리 구조를 정한다.
- Python 가상 환경과 의존성을 구성한다.
- 환경 변수 설정 방식을 정한다.
- SQLite 연결 및 세션 관리 코드를 작성한다.
- 개발용 데이터베이스 파일이 버전 관리에 포함되지 않도록 설정한다.

완료 조건:

- 애플리케이션이 실행된다.
- SQLite 연결이 정상적으로 초기화된다.
- 환경별 설정을 소스 코드에 하드코딩하지 않는다.

### 단계 2. 사용자 모델과 회원가입

- `users` 테이블을 만든다.
- 이메일을 정규화하고 유일하게 관리한다.
- 이메일 형식과 비밀번호 기본 조건을 검증한다.
- 비밀번호를 Argon2 또는 bcrypt로 해시해 저장한다.
- 중복 이메일에는 `409 Conflict`를 반환한다.
- 회원가입 성공에는 `201 Created`를 사용한다.

완료 조건:

- 유효한 이메일로 회원가입할 수 있다.
- 잘못된 이메일과 짧은 비밀번호가 거부된다.
- 데이터베이스에 평문 비밀번호가 저장되지 않는다.
- 중복 이메일이 데이터베이스 제약과 API 양쪽에서 처리된다.

### 단계 3. 로그인과 JWT 인증

- 로그인 요청 및 토큰 응답 스키마를 정의한다.
- 가입된 이메일과 비밀번호를 안전하게 검증한다.
- 성공 시 만료 시간이 포함된 JWT 액세스 토큰을 발급한다.
- JWT 시크릿, 알고리즘, 만료 시간을 환경 변수로 관리한다.
- 인증 의존성을 만들고 보호 API에 적용한다.
- 존재하지 않는 이메일과 잘못된 비밀번호에 동일한 인증 오류를 반환한다.
- `GET /api/auth/me`로 현재 로그인 사용자를 확인한다.

완료 조건:

- 가입하지 않은 사용자는 로그인할 수 없다.
- 올바른 자격 증명으로만 토큰이 발급된다.
- 유효하지 않거나 만료된 토큰은 `401 Unauthorized`가 된다.
- 보호 API가 인증 없이 호출되지 않는다.

### 단계 4. 게임 기록 저장

- `game_records` 테이블을 만든다.
- 사용자와 기록 사이의 외래 키를 설정한다.
- 점수, 줄 제거 수, 레벨 등 확장 가능한 통계를 정의한다.
- 점수는 0 이상만 허용한다.
- 기록 생성 시각은 서버가 관리한다.
- `POST /api/games/records`에 JWT 인증을 적용한다.
- 게임마다 새 기록을 추가하고 기존 기록을 수정하거나 덮어쓰지 않는다.
- `GET /api/games/records/me`로 현재 사용자의 기록을 조회한다.

완료 조건:

- 인증된 사용자의 게임 종료 시 기록이 한 건 저장된다.
- 음수 점수가 거부된다.
- 한 사용자의 여러 게임이 각각 별도 기록으로 저장된다.
- 인증되지 않은 사용자는 기록을 저장할 수 없다.

### 단계 5. 최고점수 API

- `GET /api/scores/highest`를 구현한다.
- 모든 사용자의 게임 기록을 대상으로 최고점수를 조회한다.
- 점수가 같으면 `played_at`이 더 이른 기록을 우선한다.
- 최고점수 사용자의 이메일 또는 안전한 식별 정보를 반환한다.
- 기록이 없으면 명확한 빈 응답을 반환한다.
- 최고점수 조회는 기본적으로 로그인 없이 허용한다.

완료 조건:

- 전체 사용자 중 최고점수가 조회된다.
- 동점 처리 기준이 항상 동일하게 적용된다.
- 기록이 없는 데이터베이스에서도 오류가 발생하지 않는다.

### 단계 6. 프론트엔드 연동

- 회원가입 및 로그인 화면을 구현한다.
- JWT를 이용해 인증 상태를 관리한다.
- 인증 만료와 로그아웃 상태를 처리한다.
- 로그인하지 않은 사용자가 필요한 작업을 시도하면 로그인 흐름으로 안내한다.
- 게임 종료 이벤트에서 기록 저장 API를 한 번만 호출한다.
- 기록 저장이 성공하면 최고점수를 다시 조회한다.
- 로딩, API 오류, 네트워크 실패, 빈 최고점수 상태를 표시한다.
- API 기본 URL과 CORS 설정을 환경별로 분리한다.

완료 조건:

- 회원가입 후 로그인할 수 있다.
- 로그인 후 게임 기록이 저장된다.
- 게임 기록 저장 후 화면의 최고점수가 갱신된다.
- 인증 및 네트워크 오류가 사용자에게 이해 가능한 메시지로 표시된다.

### 단계 7. 문서화와 품질 정리

- OpenAPI 문서에 인증 필요 여부와 요청·응답 예시를 작성한다.
- README에 설치, 환경 변수, 실행, 테스트 방법을 기록한다.
- 민감한 정보가 로그와 응답에 노출되지 않는지 확인한다.
- CORS 허용 출처를 개발·운영 환경에 맞게 제한한다.
- 클라이언트 점수 검증의 한계와 향후 서버 권위형 검증 방안을 문서화한다.

## 4. 테스트 계획

### 백엔드 테스트

- 정상 회원가입
- 이메일 형식 오류
- 중복 이메일 회원가입
- 정상 로그인
- 잘못된 비밀번호 로그인
- 존재하지 않는 이메일 로그인
- 인증 없이 보호 API 호출
- 인증된 게임 기록 저장
- 음수 점수 거부
- 여러 게임 기록의 개별 저장
- 전체 기록 중 최고점수 조회
- 기록이 없는 최고점수 조회
- 동점 최고점수의 선착순 정렬

### 프론트엔드 핵심 흐름

- 회원가입 후 로그인
- 로그인 후 게임 플레이 및 기록 저장
- 기록 저장 후 최고점수 갱신
- 인증 만료 표시
- API 오류와 네트워크 실패 표시

## 5. 최종 검증 기준

- `uvicorn app.main:app --reload`로 백엔드가 실행된다.
- SQLite 데이터베이스가 정상적으로 초기화된다.
- Swagger UI(`/docs`)에서 API 계약과 인증 요구사항을 확인할 수 있다.
- 회원가입하지 않은 사용자는 로그인할 수 없다.
- 게임 종료마다 중복 없이 기록이 한 건씩 저장된다.
- 최고점수가 전체 사용자 기록 기준으로 화면에 표시된다.
- 백엔드 테스트와 프론트엔드 핵심 흐름 검증이 통과한다.
