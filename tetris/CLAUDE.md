# 테트리스 애플리케이션 개발 지침

## 1. 프로젝트 목표

FastAPI 백엔드와 프론트엔드를 연동한 웹 기반 테트리스 애플리케이션을 구축한다.
백엔드는 SQLite를 사용하며, 이메일 회원가입을 완료한 사용자만 로그인하고 게임 기록을 저장할 수 있어야 한다.
사용자가 플레이를 종료할 때마다 점수를 기록하고, 전체 사용자 기록 중 최고점수를 화면에 표시한다.

## 2. 필수 기능

### 회원가입

- 이메일 주소와 비밀번호로 회원가입할 수 있어야 한다.
- 이메일은 필수이며 유효한 이메일 형식인지 검증한다.
- 이메일은 중복될 수 없다.
- 비밀번호는 평문으로 저장하지 않는다. Argon2 또는 bcrypt 기반 해시를 사용한다.
- 비밀번호 최소 길이 등 기본적인 입력 검증을 적용한다.
- 이미 가입된 이메일로 가입을 시도하면 명확한 오류를 반환한다.

### 로그인

- 회원가입이 완료된 이메일과 비밀번호로만 로그인할 수 있어야 한다.
- 로그인 성공 시 프론트엔드가 인증 상태를 유지할 수 있는 JWT 액세스 토큰을 발급한다.
- 보호된 API는 유효한 JWT를 요구한다.
- 존재하지 않는 이메일과 잘못된 비밀번호에 대한 오류 응답은 계정 존재 여부가 드러나지 않도록 동일한 형태로 반환한다.
- 프론트엔드는 토큰을 이용해 플레이 기록 저장 및 사용자 관련 API를 호출한다.

### 게임 기록

- 인증된 사용자가 한 게임을 종료할 때마다 다음 정보를 저장한다.
  - 사용자 ID
  - 점수
  - 플레이 시작 또는 종료 시각
  - 필요할 경우 레벨, 줄 제거 수 등 확장 가능한 게임 통계
- 점수는 음수가 될 수 없도록 검증한다.
- 기록은 삭제하거나 덮어쓰지 않고 매 게임마다 새로 저장한다.
- 서버가 기록 생성 시각을 관리해 클라이언트가 임의로 조작하지 못하게 한다.

### 최고점수

- 전체 사용자의 게임 기록 중 가장 높은 점수를 조회하는 API를 제공한다.
- 화면에는 최고점수와 해당 점수의 사용자 이메일 또는 안전하게 표시할 수 있는 사용자 식별 정보를 표시한다.
- 기록이 없는 경우도 정상적인 빈 상태로 처리한다.
- 최고점수 조회 API는 로그인 전에도 사용할 수 있도록 설계할 수 있다. 공개 여부를 변경할 경우 API 문서와 프론트 동작을 함께 수정한다.
- 동점자 처리 기준을 정한다. 기본 기준은 더 먼저 달성한 기록을 우선한다.

## 3. 권장 기술 스택

### 백엔드

- Python 3.11 이상
- FastAPI
- Uvicorn
- SQLAlchemy 2.x 또는 SQLModel
- SQLite
- Pydantic v2
- `pwdlib` 또는 `passlib`과 Argon2/bcrypt
- `python-jose` 또는 PyJWT
- 이메일 형식 검증을 위한 Pydantic `EmailStr`

### 프론트엔드

- 기존 프론트엔드 프레임워크가 있으면 기존 구조와 상태 관리 방식을 우선한다.
- 별도 기준이 없으면 React와 TypeScript를 우선 검토한다.
- 백엔드 API의 요청/응답 타입을 기준으로 API 클라이언트를 작성한다.
- 개발 환경에서는 CORS 허용 출처를 명시하고, 운영 환경에서는 프론트엔드 도메인만 허용한다.

프로젝트에 이미 구조가 존재하면 무리하게 재구성하지 말고, 현재 구조에 맞춰 모듈을 배치한다.

## 5. 데이터베이스 설계 기준

최소한 다음 테이블을 둔다.

### users

- `id`: 정수 기본 키
- `email`: 유일한 이메일
- `password_hash`: 비밀번호 해시
- `created_at`: 가입 시각

### game_records

- `id`: 정수 기본 키
- `user_id`: `users.id`를 참조하는 외래 키
- `score`: 정수 점수
- `lines_cleared`: 제거한 줄 수 등 선택 통계
- `played_at`: 기록 저장 시각

인덱스와 외래 키를 설정하고, 점수 및 시각 정렬이 효율적으로 동작하도록 필요한 인덱스를 추가한다.
개발용 SQLite 파일은 버전 관리에 포함하지 않는다. 마이그레이션 도구를 도입하면 스키마 변경을 마이그레이션으로 관리한다.

## 6. API 계약

기본 경로는 `/api`로 통일한다.

- `POST /api/auth/register`
  - 이메일과 비밀번호를 받아 회원가입
- `POST /api/auth/login`
  - 이메일과 비밀번호를 받아 액세스 토큰 발급
- `GET /api/auth/me`
  - 현재 로그인한 사용자 확인
- `POST /api/games/records`
  - 인증된 사용자의 게임 결과 저장
- `GET /api/scores/highest`
  - 전체 사용자 중 최고점수 조회
- `GET /api/games/records/me`
  - 현재 사용자의 게임 기록 조회

응답 형식과 상태 코드를 일관되게 유지한다.

- 회원가입 성공: `201 Created`
- 기록 생성 성공: `201 Created`
- 조회 성공: `200 OK`
- 잘못된 입력: `422 Unprocessable Entity`
- 인증 실패: `401 Unauthorized`
- 중복 이메일 등 충돌: `409 Conflict`

OpenAPI 문서에서 각 엔드포인트의 인증 필요 여부, 요청 예시, 응답 예시, 오류 형식을 명확히 설명한다.

## 7. 인증 및 보안

- JWT 시크릿과 만료 시간은 환경 변수로 관리한다.
- 시크릿, 비밀번호, 액세스 토큰을 소스 코드나 로그에 기록하지 않는다.
- 비밀번호 비교는 안전한 해시 검증 함수를 사용한다.
- JWT의 알고리즘과 만료를 검증한다.
- CORS는 허용할 프론트엔드 주소를 제한한다.
- 게임 점수는 클라이언트 입력을 그대로 신뢰하지 않는다. 현재 과제 범위에서 서버 검증이 어렵다면 그 한계를 문서화하고, 추후 리플레이 검증 또는 서버 권위형 게임 로직을 고려한다.

## 8. 프론트엔드 연동 기준

- 회원가입, 로그인, 로그아웃, 인증 만료 상태를 사용자에게 명확히 보여준다.
- 로그인하지 않은 사용자가 게임을 시작하거나 기록을 저장하려 할 때 로그인 흐름으로 안내한다.
- 게임 종료 시 `POST /api/games/records`를 한 번만 호출해 중복 기록을 방지한다.
- 기록 저장 성공 후 최고점수를 다시 조회해 화면을 갱신한다.
- 로딩, 오류, 빈 기록, 네트워크 실패 상태를 모두 처리한다.
- 백엔드의 CORS 설정과 프론트엔드의 API 기본 URL을 환경별로 분리한다.
- API 오류 메시지는 내부 구현 정보나 민감한 정보를 노출하지 않는 사용자용 문구로 변환한다.

## 9. 테스트 요구사항

백엔드에는 최소한 다음 테스트를 작성한다.

- 정상 회원가입
- 이메일 형식 오류
- 중복 이메일 회원가입
- 정상 로그인
- 잘못된 비밀번호 로그인
- 인증 없이 보호 API 호출
- 인증된 사용자의 게임 기록 저장
- 음수 점수 거부
- 한 사용자의 여러 게임 기록이 각각 저장되는지 확인
- 전체 기록 중 최고점수 조회
- 기록이 없을 때 최고점수 빈 상태
- 동점 최고점수의 정렬 기준

프론트엔드에는 최소한 다음 흐름을 확인한다.

- 회원가입 후 로그인
- 로그인 후 게임 기록 저장
- 저장 후 최고점수 갱신
- 인증 만료 또는 API 오류 표시

## 10. 실행 및 검증

백엔드 개발 실행 예시:

```bash
uvicorn app.main:app --reload
```

테스트 실행 예시:

```bash
pytest
```

구현을 완료하기 전에 다음을 확인한다.

1. 백엔드가 SQLite 데이터베이스를 정상적으로 초기화하는가.
2. Swagger UI(`/docs`)에서 인증이 필요한 API를 확인할 수 있는가.
3. 프론트엔드가 백엔드 API 주소로 요청을 보내는가.
4. 회원가입하지 않은 사용자는 로그인할 수 없는가.
5. 게임 종료마다 기록이 한 건씩 저장되는가.
6. 최고점수가 전체 사용자 기록을 기준으로 표시되는가.
7. 백엔드 테스트와 프론트엔드 핵심 흐름 검증이 통과하는가.

## 11. 구현 우선순위

1. 백엔드 프로젝트와 SQLite 연결
2. 사용자 모델 및 회원가입/로그인 API
3. JWT 인증 의존성 및 보호 API
4. 게임 기록 저장 및 최고점수 조회 API
5. 프론트엔드 인증 연동
6. 게임 종료 시 기록 저장 연동
7. 최고점수 화면 표시
8. 테스트, 오류 처리, CORS, 문서 정리

각 단계가 동작하는 상태에서 다음 단계로 진행하고, API 계약이 변경되면 프론트엔드와 테스트를 함께 수정한다.
